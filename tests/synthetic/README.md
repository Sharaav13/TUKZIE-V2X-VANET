# SYNTHETIC test logs (not measured)

Everything in this folder is **synthetic**. The logs were generated by `make_synthetic.py` from the real logs in
`tests/`, to show what the **current** node firmware and simulated host (`HOST_MSG = 4`) would log in the same tests.
They are for checking `test_analysis.m` and the expected firmware behaviour, and must not be reported as measured
results. The real logs in `tests/` are unchanged.

| Folder | Based on | What was changed |
|---|---|---|
| `gw parking lot/run 1` | `tests/gw parking lot/run 1` | Trimmed to start at 13:54:00 (leaves out the az dip at 13:53:36). Jolts the 1 s snapshots under-recorded are scaled to \|az − 1 g\| = 0.9 g (13:54:39) and 0.85 g (13:54:59). Beacons after a jolt carry bad terrain (code 3), the others 0. The sensor log's message column is the last beacon's code. |
| `gw parking lot/run 2` | `tests/gw parking lot/run 2` | Same rule (jolt at 16:29:20). The real run had no VANET log, so beacons are generated every 16.48 s from the sensor log. |
| `shd test` | `tests/shd test` | The host sends code 4 (`m=5` became `m=4`). Each node's myself log holds 4 until its next beacon, which carries it. Low battery (2) is flagged at battery ≤ 50 %. The codes are carried into the peer's RX/FW lines, the sensor logs and the serial monitor's RX lines. |

All other fields (times, positions, RSSI, status, tasks, battery, forwards) are the real data.

## Rebuild and analyse

```bash
python -I make_synthetic.py
```

Then in MATLAB, run `run_synthetic.m`. It copies `tests/test_analysis.m` here unchanged and runs it, writing
`plots/` and `test_results.txt` in this folder. Folders without synthetic logs report a missing-folder error.

To mark the jolts as recorded bumps on the gw plot, paste these into `GW_BUMPS` (in the copy):

```matlab
GW_BUMPS = {'13:54:39', 'Jolt 1'
            '13:54:59', 'Jolt 2'};
```
